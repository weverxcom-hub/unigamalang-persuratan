## Yang sudah baik
- Penomoran atomik: `allocateNextNumber` memakai upsert + increment di dalam transaksi, ditambah `Archive.number @unique` di DB. Jika transaksi gagal, nomor ikut rollback (tidak ada lubang nomor). Zona waktu dihitung Asia/Jakarta.
- Semua route API di luar `/api/auth/*` dan `/auth/*` memanggil `getSession` atau `CRON_SECRET`. Sesi dicek ke DB (akun nonaktif dan `sessionVersion` basi ditolak).
- Cek unit pada baca/ubah arsip, validasi kepemilikan path Blob, anti-duplikat file, cek Origin (CSRF), header keamanan, audit log, cron memakai bearer secret.
- Indeks DB wajar; daftar arsip dipaginasi (maks 200/halaman).

## Temuan (urut tingkat bahaya)
1. **Dependensi rentan (tinggi).** `next 14.2.35` punya advisory critical (RCE di Image Optimization untuk AVIF/SVG; perbaikan di 15.5.x ke atas). `zod` high (DoS memori; perbaikan non-breaking via `npm audit fix`). `prisma` 6.x ditandai high lewat `@prisma/config`/`deepmerge-ts` (perbaikan hanya di Prisma 7, major). `exceljs`→`uuid` moderate. Catatan: di Vercel, Image Optimizer dikelola platform sehingga risiko RCE lebih kecil, tapi tetap rencanakan upgrade Next ke 15.5.x terbaru dan uji penuh.
2. **File Drive publik "siapa saja dengan tautan" (tinggi untuk kerahasiaan).** `finaliseUpload` di `src/lib/gdrive.ts` memberi `reader` ke `anyone`. Surat rahasia, disposisi, dan SK kepegawaian bisa dibuka siapa pun yang memegang tautan, tanpa login, dan tidak bisa dicabut dari aplikasi. Perbaikan yang disarankan: file tetap privat dan diunduh lewat route aplikasi (service account) setelah cek hak akses.
3. **Pendaftaran mandiri tanpa verifikasi email (sedang).** `/api/auth/register` hanya mengecek akhiran `@unigamalang.ac.id`, tidak memverifikasi kepemilikan email, lalu langsung login. Orang luar bisa mendaftar atas nama alamat kampus siapa pun (akun tanpa unit, peran USER). Set `REGISTRATION_DISABLED=true` di production (sudah didukung kode).
4. **Rate limiter in-memory (sedang).** `src/lib/rate-limit.ts` menyimpan hitungan di memori per instance serverless, sehingga batas login tidak andal saat banyak instance/cold start. Untuk skala universitas, ganti ke Upstash/Redis atau tabel DB.
5. **Middleware memakai secret dev bila `AUTH_SECRET` kosong (rendah).** `src/middleware.ts` tidak ikut memvalidasi `AUTH_SECRET` seperti `getSession`; bila env kosong di production, JWT yang ditandatangani dengan secret default akan lolos pagar halaman `/dashboard` (data tetap diblok `getSession`). Pastikan `AUTH_SECRET` terisi dan, idealnya, gagalkan start bila kosong.
6. **`/api/gdrive/finalise` tidak mengecek pemilik file (rendah).** User login mana pun bisa memanggil dengan `fileId` file lain di folder induk dan membuatnya publik. Batasi ke file yang dibuat sesi tersebut.
7. **Basis data (perlu dikonfirmasi, bukan bug kode).** `docs/BACKUP-STRATEGY.md` mengandalkan PITR Neon (7 hari di paket gratis) dan `pg_dump` mingguan yang masih berupa saran. Pastikan: paket Neon production, `pg_dump` terjadwal benar-benar jalan, dan prosedur pemulihan pernah diuji sekali.
8. **Lain-lain.** Fallback `fileDataUrl` base64 di DB (deprecated) menggembungkan DB; `login` memakai `bcrypt.compareSync` (memblokir event loop, kecil dampaknya); tidak ada CSP penuh (sudah dicatat di `next.config.mjs`).
